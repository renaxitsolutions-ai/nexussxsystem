🔑 JWT — TokensAlto

Tokens firmados con HS256. Expiran en 7 días. Contienen: id, email, role, tenant_id. Verificados en cada petición por el middleware auth(). Almacenados en localStorage.

🔒 bcrypt — ContraseñasAlto

Todas las contraseñas se hashean con bcryptjs con 12 rondas de sal. Imposible revertir el hash. En comparación de login se usa bcrypt.compareSync() — nunca texto plano.

📱 2FA TOTPAlto

Estándar RFC 6238. Secreto único por usuario generado con otplib. QR code para escanear con Google Authenticator. Código de 6 dígitos que cambia cada 30 segundos. El secreto se almacena cifrado en la BD.

👥 RBAC — RolesAlto

5 roles: Owner → Admin → Manager → Agent → Viewer. Middleware requireRole(...roles) aplicado en cada endpoint. La verificación ocurre en el servidor, no solo en el cliente.

🚦 Rate LimitingAlto

Configuración por endpoint:
• Auth (login/register): 20 req / 15min
• IA endpoints: 15 req / min
• API general: 120 req / min
Bloqueo automático con error 429.

🛡️ Helmet.jsAlto

Headers HTTP automáticos: X-Frame-Options: DENY, X-Content-Type-Options, Referrer-Policy, X-XSS-Protection. Previene clickjacking, MIME sniffing y XSS reflejado.

🔍 Audit LogMedio

Cada acción sensible registra en audit_logs: usuario, email, acción, entidad afectada, cambios en JSON, dirección IP y timestamp. Inmutable — solo lectura para admin/owner.

🗄️ SQL Injection — PrevenciónAlto

100% de las queries usan prepared statements de node:sqlite. Nunca se construye SQL con interpolación de strings. Los parámetros siempre son pasados como argumentos separados.

🔑 API Keys — AlmacenamientoAlto

Las claves se generan como nxs_[32 chars aleatorios]. En base de datos se guarda solo el prefijo (8 chars) y el hash SHA-256. La clave completa solo se muestra una vez al crearla.

⚠️ HTTPS/TLSRecomendado

No implementado en el entorno de desarrollo local. Para producción se requiere certificado SSL/TLS (Let's Encrypt es gratuito) configurado en Nginx como reverse proxy frente a Express.

🔐 Contraseñas en .envMedio

Las claves sensibles (ANTHROPIC_API_KEY, JWT_SECRET, SMTP_PASS) están en server/.env que nunca debe subirse a Git. El archivo .gitignore debe incluirlo explícitamente.

🌐 CORSMedio

Configurado con origin: '*' en desarrollo para facilitar las pruebas. En producción debe restringirse al dominio propio. Configuración centralizada en el middleware de Express.
